# Node count breakdown (total = 300):
#   p  (pedestrians)  = 180
#   c  (cars)         =  75
#   w  (wifi APs)     =  21
#   t3 (tram line 3)  =   6
#   t4 (tram line 4)  =  12
#   t10(tram line 10) =   6
#                        ---
#                        300
#
# Energy tuning rationale:
#   initialEnergy = 10800 J (~3 Wh smartphone battery)
#   scanEnergy    = 0.001  J/s  -> 43.2 J/12h = 0.4% from idle scan alone
#   txEnergy      = 0.000005 J/byte -> 500KB msg = 2.5 J per relay
#   rxEnergy      = 0.000003 J/byte -> 500KB msg = 1.5 J per receive
#   moveEnergy    = 0.0005  J/s  -> walking cost stays realistic
#
#   At these rates a very active relay node (500 messages x 750KB avg):
#     tx: 500 x 750000 x 0.000005 = 1875 J  (17%)
#     rx: 500 x 750000 x 0.000003 = 1125 J  (10%)
#     scan: 43.2 J                           (0.4%)
#   Total drain ~28% -- meaningful variation, no mass death
#
